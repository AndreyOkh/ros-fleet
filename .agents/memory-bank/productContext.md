# Product Context

## Problems Solved
- **Фрагментация бэкапов MikroTik:** В организациях с десятками/сотнями роутеров ручной сбор бэкапов приводит к пропускам, устаревшим конфигурациям и потере данных при авариях.
- **Шум в Git при бэкапах:** Стандартная команда RouterOS `/export` добавляет дату и время в первой строке. Если экспортировать конфигурацию без очистки, Git регистрирует изменения каждый день, даже если конфигурация не менялась. `ros-fleet` нормализует заголовок и фиксирует только реальные диффы.
- **Сложность управления учетными данными:** Наличие глобального блока `defaults` в `config.json` позволяет не дублировать порты, SSH-ключи и пароли шифрования для каждого устройства, а гибко переопределять их при необходимости.
- **Отсутствие мгновенной видимости парка:** Встроенный Web UI на HTMX сразу после старта сервиса отображает текущее состояние устройств из кэшированного `state.json` без ожидания долгого SSH-опроса.

## Key Workflows
1. **Плановое резервное копирование:**
   - Планировщик `scheduler` срабатывает в заданное время суток (`schedule.times`, с учетом `schedule.timezone`).
   - Для каждого роутера запускается сбор бинарного бэкапа (сохраняется в `binary_backup_dir` с таймстемпом) и текстового экспорта.
   - Текстовый экспорт нормализуется и сохраняется в `export_dir/<router>.rsc`.
   - Запускается единый Git-коммит: если были изменения, создается коммит и опционально выполняется `git push`.
   - Происходит ротация бинарных файлов (удаление копий старше `retention_days`).
   - Отправляется отчет в Telegram (если настроен).
2. **Ручной запуск:**
   - Через Web UI (кнопка запуска бэкапа) или через CLI с флагом `-run-now`.
3. **Управление роутерами через Web UI:**
   - Добавление, редактирование и удаление роутеров с интерактивными сегментными переключателями наследования дефолтных настроек.
