    - Реализованы кастомные выпадающие списки мультивыбора для колонок «Модель», «Версия ROS», «Статус бэкапа» и «Активность»:

      - Бейджи с количеством выбранных элементов на кнопках фильтров.
      - Сохранение состояния фильтров в `sessionStorage` (фильтры сохраняются при обновлении страницы или перезагрузке данных).
    - Устранена причина сброса фильтров:
      - Ранее периодические запросы `/routers/table` и `/dashboard/summary` перезаписывали DOM, а генерация `<option>` динамически затирала выбранные значения в нативных `<select>`.
      - Состояние фильтров теперь отвязано от DOM-дерева и хранится в независимом `filterState` (на базе `Set`). При любом обновлении таблицы через HTMX (`htmx:afterSwap`) фильтры синхронно повторно применяются к новым строкам.
    - Устранено мерцание таблицы:
      - Убран безусловный холостой опрос `/routers/table` каждые 15 секунд в спокойном состоянии. Поллинг таблицы теперь активируется **только во время активного процесса бэкапа** внутри баннера `backup-running-banner` (`every 8s`).
    - Исправлен баг скрытия всех строк при фильтрации:
      - Ранее добавленный CSS-селектор `#routers-table-container.is-filtered tr[data-name] { display: none; }` приводил к тому, что при `row.style.display = ''` (очистка инлайн-стиля для совпавших строк) браузер применял CSS-правило `display: none;`, скрывая вообще все строки таблицы.
      - Селектор полностью удален, фильтрация переведена на стандартное управление отображением строк таблицы (`display = ''` / `display = 'none'`), поддержана обработка не определенных моделей/версий (`Unknown`).
  - **Устранение обрыва массового бэкапа ("Global context cancelled") и асинхронный запуск:**
    - Выявлена причина падения общего бэкапа на 61-м роутере: `handleBackupAll` передавал контекст HTTP-запроса `r.Context()` в синхронный вызов `s.runner.Run(r.Context())`. При длительной работе (~77 секунд) браузер или прокси закрывали соединение / таймаутили запрос, что приводило к отмене `r.Context()` и прерыванию бэкапа оставшихся 64 устройств и отмене `git add/commit/push`.
    - `handleBackupAll` переведен на асинхронный запуск в фоновой горутине под управлением долгоживущего контекста приложения `s.appCtx` (`context.WithCancel`). HTTP-запрос теперь завершается мгновенно (~10мс), исключая любые таймауты браузера или прокси.
    - В `Runner` добавлен атомарный флаг `isRunning atomic.Bool`, предотвращающий одновременный запуск двух параллельных циклов бэкапа.
    - В UI над таблицей устройств добавлен анимированный баннер `backup-running-banner`, информирующий о фоновом выполнении копирования, а для таблицы устройств включен периодический поллинг раз в 15 секунд (`hx-trigger="every 15s"`), отображающий прогресс выполнения в реальном времени.
    - Для одиночных бэкапов `handleBackupSingle` применен `context.WithoutCancel(r.Context())` с таймаутом, исключающий разрыв соединения при перезагрузке страницы пользователем.

Кнопка `Push` отображается только тогда, когда локальный репозиторий опережает удаленный (`Ahead > 0`) или произошла ошибка отправки (`LastError != ""`).   - **Исправление ошибки записи файлов при монтировании в Docker (EBUSY / "device or resource busy"):**
    - Выявлена причина ошибки при переключении активности роутера или сохранении настроек в Docker: при bind-mount одного файла (`./config.json:/app/config.json:rw`, `./state.json:/app/state.json:rw`) целевой файл в Linux является точкой монтирования, из-за чего системный вызов `rename()` возвращает `EBUSY`.
    - В `internal/config`, `internal/state` и `internal/storage` реализован умный фолбэк: при ошибке `rename()` данные открываются через прямой дескриптор с `O_TRUNC` и сбрасываются на хост через `fsync`, гарантируя корректное сохранение файлов как в обычном окружении, так и внутри контейнеров Docker.
